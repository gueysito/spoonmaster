# Demo spine and flows

The hackathon demo must be under 90 seconds and show the plugin working. Use real
Tokyo venues and live evidence. Feedback in the demo is labeled as a demo input, never
presented as a meal the presenter ate.

## Spine (90 seconds)

| Time | Beat | Shows |
|---|---|---|
| 0-10s | "Dinner nearby, nothing fussy" with a Shibuya pin. The ledger runs: "Considered 47, recommended 3." | Agentic checks are visible |
| 10-30s | The pick card: what to order, open-at-arrival math, ETA, cost, map link. Runner-up and wildcard below. | Tappable, priced, useful |
| 30-55s | Feedback: "loved it, but the sauce was too sweet and it was loud." The taste diff appears with scope tags. | Learning the user can see |
| 55-75s | The same ask again. The ranking shifts and states why. | Memory changes behavior |
| 75-90s | Closer: two agents merge profiles for "dinner for both of us", or the order card. | Beyond a prompt or a skill |

## Alternative flows to riff on

### A. New city arrival
Pin in an unfamiliar city. The locale scout proposes a ladder ("locals here use X for
quality, Y for hours"), the user confirms, then the first recommendation uses it.

### B. Household night
Two adults and a five-year-old, transit only, kid bedtime at 20:00. The ledger shows
"removed: last seating after bedtime", "removed: 25-minute queue". The pick explains
the fit for each person.

### C. Photo to table
User sends a photo of a dish seen online. The plugin names the dish and cuisine and
finds the best nearby place that serves it, with an order card.

### D. "Why not that place?"
User asks why a famous spot was skipped. `/why` shows its gate: closed at arrival,
last order 21:30, ETA 22 minutes.

### E. Rain pivot
Same ask in heavy rain. Travel gates tighten, covered options rise, and the card says so.
